# IwaraTool v1.2.3

本次为修复版：修复中心能识别更多浏览器下载的视频文件名，识别不到的视频可以在修复列表里手动填写 Iwara ID（[#32](https://github.com/Moeary/IwaraTool/issues/32)）。

## 文件名识别

- 支持 `Iwara - 标题 [视频ID] [Source].mp4` 这类浏览器 / yt-dlp 风格的文件名：方括号、圆括号、花括号或【】中的视频 ID 会被识别。
- 不再把 `Iwara - ` 后面的第一个词（如 `SEXDance`、`TimeStop`）当成视频 ID，这类文件以前会报“作品不存在或当前账号不可见”。只有带 `id` 标记（如 `iwara-id=…`、`Iwara ID …`、`video_id: …`、`id=…`）或 Iwara 视频链接中的 ID 才会被直接采用；标题里普通的 “ID” 一词（如 `My ID Challenge`）不算标记。
- 没有标记的 ID 候选（括号中的 ID、规则命名末尾的 `_{id}`、文件名里其他像 ID 的片段）会先经 Iwara 确认，再考虑本地同名记录，避免关联到恰好同名的另一部作品；确认不了就依次尝试下一个候选，最多 3 个，之后再按本地记录和标题搜索。
- 标题里带句点（如 `Part 1.5 [ID]`）时不再丢失后面的 ID。
- 按标题搜索时会去掉 `Iwara - ` 前缀、`[Source]` / `[1080p]` 等画质标记和 ID 片段，搜索词更接近原标题；括号里的内容若其实是标题的一部分（如 `Dance [2024Edition]`），匹配时也会连同它一起比对，并优先于去掉括号后的结果（不会误认成另一部叫 `Dance` 的作品）。

## 手动填写 Iwara ID

- 修复列表中“跳过”“待确认”等未完成的行，可双击“Iwara ID”列，填写视频 ID 或 iwara.tv / iwara.ai 的视频链接，按回车后会按该 ID 重新查询并生成目标路径，同时重新检查与其他文件的冲突。
- 粘贴 iwara.ai 链接时，历史记录中的作品链接会保留 iwara.ai 域名。
- 已识别但匹配错误的行也可以这样改正（多次改填也一样），补录历史时会解除原先那条记录与该文件的关联，下次扫描不会再认回旧作品；已完成的行不可修改。扫描或修复进行中暂不能编辑，查询中点“停止”会丢弃结果并还原该行。
- 修复时已移动、但写入封面 / NFO / 历史失败的行，改 ID 后按文件当前位置重新规划。
- 填写的内容不是有效 ID 或链接时会提示并还原；查询不到该视频（或网络失败）时该行保持“跳过”，详情中显示所填 ID 与原因，可再次填写同一个 ID 重试。
- 同一文件在历史中有多条记录时，扫描以最新的一条为准。

## 下载

- Windows AMD64：`IwaraTool-Windows-AMD64-v1.2.3.exe`。
- Linux AMD64：`IwaraTool-Linux-AMD64-v1.2.3`。
- macOS Apple Silicon：`IwaraTool-macOS-AppleSilicon-ARM64-v1.2.3.dmg`（另附同内容的 `.zip`）。
- macOS Intel：`IwaraTool-macOS-Intel-x86_64-v1.2.3.dmg`（另附同内容的 `.zip`）。
- 应用内不提供自动替换更新：请从 Release 页面下载新版本覆盖旧程序，设置、队列与历史都会保留。
