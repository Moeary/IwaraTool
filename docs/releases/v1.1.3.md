# IwaraTool v1.1.3

本次更新让每个页面使用各自的下载规则（[#13](https://github.com/Moeary/IwaraTool/issues/13)），新增“临时下载”规则，并为 Windows 发布包加入版本信息与代码签名流程。

## 每页独立的下载规则

- 订阅、搜索、视频详情、首页与下载链接各自保存所选规则，不再共用一个全局生效的规则；页面设为“跟随默认”时，使用规则页中标有 ● 的默认规则。
- 规则页新增“每页规则”一行选择器，置于规则列表与编辑器之上，不再看起来像是所选规则的一部分；列表中的每条规则会注明哪些页面正在使用它。
- 新增可编辑的“临时下载”规则，保存到 `temp_video/{title}_{id}.mp4` 且不写入历史，是搜索与视频详情的默认规则。
- 临时副本不再阻碍之后对同一视频的正式下载：已完成的任务在再次入队时被释放，不计入已有文件索引；无历史规则的固定前置文件夹在建立索引时被跳过。

## Windows 发布与签名

- 新增 `scripts/build_windows.py` 取代 `pixi run build` 与发布流程中的内联 Nuitka 命令：写入公司、产品、版本与版权信息；设置 `WINDOWS_SIGN_PFX` / `WINDOWS_SIGN_PFX_BASE64` 与 `WINDOWS_SIGN_PFX_PASSWORD` 后会自动做 Authenticode 签名并加时间戳；`--sign-only <exe>` 可只签名已有文件。
- 标签构建可经 SignPath 签名 Windows exe，并在替换前校验 Authenticode 状态；设置 `SIGNPATH_ORGANIZATION_ID` 之前这些步骤会被跳过。
- 英文 readme 新增“Code signing policy”与隐私说明，列出程序会访问的全部服务。
- 在已激活的 pixi 终端中再次运行 pixi 时，不再出现 `SSL_CERT_DIR` 为空的警告。

## 文档

- readme 的截图改为以英文界面、示例数据重新截取，且不含任何封面或头像图片。

## 下载

- Windows AMD64：`IwaraTool-Windows-AMD64-v1.1.3.exe`。
- Linux AMD64：`IwaraTool-Linux-AMD64-v1.1.3`。
- macOS：`IwaraTool-macOS-ARM64-v1.1.3.zip` / `IwaraTool-macOS-AMD64-v1.1.3.zip`。未使用 Developer ID 签名与公证；若系统阻止打开，请按“隐私与安全性”的提示允许该应用。
- 应用内不提供自动替换更新：请从 Release 页面下载新版本，覆盖旧程序即可，程序旁的 `data` 目录会保留全部设置、队列与历史。
- 每个发布包附带 `.sha256` 校验文件。
