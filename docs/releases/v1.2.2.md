# IwaraTool v1.2.2

本次更新可以在队列空闲后自动重试因网络问题失败的下载，并按报错内容决定是否重试（[#30](https://github.com/Moeary/IwaraTool/issues/30)）。

## 失败任务自动重试

- “应用设置 → 下载 → 并发”在“任务空闲后自动恢复超时中断项”下新增“任务空闲后立即重试网络类失败项”：队列中没有排队或进行中的任务时，失败项会立即重新加入队列。
- 按报错内容判断（报错里带明确的 HTTP 状态码时以状态码为准）：连接中断（如 `Connection broken: IncompleteRead(...)`）、超时、HTTP 429 / 5xx、下载不完整等会重试，并从已下载的部分续传；私有作品、作品不存在、账号未登录 / 无权限或无法观看、YouTube 外部嵌入等不会重试。无法识别的报错默认不重试，避免反复失败。
- 可填写“总是重试的报错关键词”与“不重试的报错关键词”（逗号分隔，匹配报错原文），“不重试”优先。
- 每个任务的自动重试次数有上限（默认 3 次，可设 1–20），重启后保留计数；手动点“重试”或“全部重试”会重新计数。
- 超时中断项的自动恢复与失败项重试在同一次空闲时一起入队，互不抢占；每个超时中断项最多自动恢复 10 次，手动“复原”后重新计数。
- 只有上一次的解析 / 下载线程确实退出后才会自动或手动恢复，避免卡住的旧线程与新任务同时写同一文件（手动“复原”时会提示“仍在停止中”）；手动重试清理缓存期间，自动重试不会接手该任务。
- 程序启动完成之前、启动时自动登录尚未结束时、以及退出过程中，不做自动恢复或重试。
- 下载工作台中等待确认的视频不再阻止“空闲后自动恢复超时中断项”生效。

## 续传更可靠

- 临时文件旁会记下它对应的文件与画质、由哪个下载器（内置 / aria2）写入以及完整大小（`*_temp.resume.json`）。重新解析后若文件或画质变了、换了下载器、服务器返回的总大小对不上，或返回 416 却无法确认文件完整，都会清除缓存从头下载，不再把不同内容拼接后标为完成；缓存删不掉时本次下载直接失败，不会继续续传。
- 旧版本留下、没有这份记录的临时文件无法确认来源，升级后第一次会从头下载。
- “清理临时文件”、中断时删除缓存以及重试前的清理都会一并删除这些记录（包括已失去临时文件的孤立记录）。
- 远端 aria2（NAS）的续传仍由远端 aria2 自行处理，本机无法校验。

## 仓库整理

- 构建与辅助脚本移至 `scripts/tools/`，测试移至 `scripts/tests/`；简体中文与日文说明移至 `docs/readme/`。`pixi run test` / `pixi run build` 用法不变。

## 下载

- Windows AMD64：`IwaraTool-Windows-AMD64-v1.2.2.exe`。
- Linux AMD64：`IwaraTool-Linux-AMD64-v1.2.2`。
- macOS Apple Silicon：`IwaraTool-macOS-AppleSilicon-ARM64-v1.2.2.dmg`（另附同内容的 `.zip`）。
- macOS Intel：`IwaraTool-macOS-Intel-x86_64-v1.2.2.dmg`（另附同内容的 `.zip`）。
- 应用内不提供自动替换更新：请从 Release 页面下载新版本覆盖旧程序，设置、队列与历史都会保留。
