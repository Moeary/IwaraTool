# PySide6 迁移 Flet 可行性

评估日期：2026-11-19。结论：**可保留 Python 核心，新增 Flet 前端；完整替换桌面版需要重写界面并重新验证平台集成。** 建议先做可独立运行的验证版本，通过性能、播放和打包验收后再决定是否替换现有前端。

## 仓库现状

当前 `app/ui` 约 3.6 万行 Python，209 个模块中有 159 个直接引用 PySide6 或 qfluentwidgets；Qt 控件、布局、表格、信号和生命周期不能直接转换为 Flet 控件。`app/core` 约 1.8 万行、103 个模块，只有 `net_policy.py` 包含可选的 QThread 中断查询。

已有基础能显著减少后端迁移量：

- `app/qt_support.py` 支持在导入应用模块前设置 `IWARATOOL_NO_QT=1`。
- `app/settings_store.py` 提供兼容 QSettings INI 的纯 Python 设置存储；`app/events.py` 提供纯 Python 事件。
- `scripts/tests/test_core_without_qt.py` 在拒绝导入 PySide6 的新解释器中检查全部核心模块，以及配置、事件和翻译。
- API、搜索归一化、横竖屏筛选、SQLite 历史、订阅、下载规则、命名、FFmpeg 工具可以从核心层复用。

上述模块规模基于本次修改后的源码统计，行数仅用于说明重写范围，不代表工期。

## 功能迁移范围

| 部分 | 可复用内容 | 需要重做或验证 |
| --- | --- | --- |
| 搜索和首页 | API、数据模型、分页、标签、筛选 | 卡片、菜单、多选、布局、搜索历史和导航 |
| 下载与订阅 | 调度、历史、规则、订阅自动化 | 进度事件接入、取消、错误提示、关闭时保存 |
| 历史与修复 | SQLite、文件管理、批量修复 | 表格排序、列配置、封面视图、大数据量交互 |
| 设置与翻译 | 设置键、INI、`tr()`、已有翻译文本 | 设置表单、动态刷新、字体和主题 |
| 播放器 | 本地文件定位、远程地址解析 | QtMultimedia 替换、跳转、音量、弹出、代理和 HTTP 头 |
| 系统功能 | 文件夹打开、部分平台辅助函数 | 托盘、全局快捷键、通知、自启动、窗口关闭策略 |
| 发布 | 资源清单、现有验证媒体 | Flet 打包、CI、签名、升级、三平台运行时验证 |

Flet 的 `GridView` 提供按需构建可见控件的能力，适合封面浏览。但 Python 端数据量、控件序列化和图片缓存仍需用实际数据衡量；不能据此认定整个历史库可一次装入而没有成本。[GridView 官方文档](https://flet.dev/docs/controls/gridview/)

## 并发和关闭流程

Flet 当前文档说明应用事件处理基于 asyncio；同步 HTTP 或磁盘批处理应通过 `asyncio.to_thread()` 或受控线程池执行，避免阻塞界面。[异步应用官方文档](https://flet.dev/docs/cookbook/async-apps/)

建议新增独立入口和服务适配层：

1. 在任何 `app` 导入前设置 `IWARATOOL_NO_QT=1`，使 Flet 环境不依赖 Qt 事件循环。
2. 后台线程发出的纯 Python 事件通过 `loop.call_soon_threadsafe()` 交给前端队列；只在所属页面的事件循环中更新控件。
3. 下载进度按任务合并，以约 100–200ms 的批次刷新；任务完成、失败等状态立即排队处理。此间隔是验证阶段的初始参数。
4. 页面卸载时取消订阅事件；窗口关闭前停止刷新、保存队列、等待下载与数据库退出，再销毁窗口。保留现有核心的关闭顺序并补上 Flet 生命周期适配。

不能同时沿用 Qt 信号后端并省略 Qt 事件循环，否则跨线程投递可能无法到达。纯 Python 事件会在发出事件的线程直接调用订阅者，也不能直接操作界面。

## 播放和打包

Flet 的播放器通过独立 `flet-video` 扩展接入 `media_kit`。这提供替换 QtMultimedia 的路径，但仍需实测 Iwara 流、带请求头的媒体、代理、过期地址更新、本地 H.264/AAC、跳转和全屏。Linux 完整客户端还涉及 libmpv 与 GStreamer 运行库。[Video 官方文档](https://flet.dev/docs/controls/video/)

Flet 提供 `flet build`；macOS 可生成通用应用包，也可限定架构，但必须检查所有 Python 依赖的目标架构 wheel。现有 Nuitka 的 PySide6 插件及 Qt 插件复制逻辑需替换，DMG 布局和媒体冒烟验证思路可保留。代码签名、公证及 Windows 发布签名仍是单独的发布步骤。[macOS 打包官方文档](https://flet.dev/docs/publish/macos/)、[Windows 打包官方文档](https://flet.dev/docs/publish/windows/)

桌面是最接近现有行为的第一目标。静态 Web 运行于 Pyodide，线程、任意本机路径、子进程和现有 FFmpeg 调用不能按桌面方式直接复用；动态 Web 则需要服务端存储、任务隔离与账号隔离，属于另一项架构工作。[异步应用的平台差异](https://flet.dev/docs/cookbook/async-apps/)

## 建议的验证阶段

先用独立 Pixi 环境固定 Flet 及扩展版本，保持现有桌面入口可运行。按以下顺序逐步验收：

1. **搜索和下载闭环**：读取隔离 INI，搜索和翻页、横竖屏筛选、单项下载、进度、取消、历史定位。前端运行时不加载 PySide6。
2. **性能和事件**：比较现有 Qt 与 Flet 在同一台机器上的 32／100 张封面、1 万条历史、3 个并发下载时的启动时间、滚动、响应和内存；检查事件不丢失、卸载后不重复订阅。
3. **媒体和桌面集成**：验证本地／远程播放、请求头、代理、托盘继续下载、关闭与重开恢复、文件夹打开和通知。托盘能力及所需扩展在此阶段确认。
4. **发布**：先构建 Apple Silicon 包，在全新数据目录和含空格路径下运行；再验证 Intel、Windows、Linux 的依赖、签名、升级与播放。

验证通过后，再迁移规则编辑、订阅、历史、修复、工具和设置。核心单元测试继续使用，界面测试需按 Flet 重建。若主要目标只是修复现有桌面体验，保留 PySide6 的改动范围较小；若目标包含共享桌面与移动界面，Flet 值得先进行上述验证。
